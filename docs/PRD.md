# workOS-Agent — 컨셉 & 목적

## 해결하려는 문제

에이전트 코딩에는 구조적인 함정이 있다.

- **한 번에 너무 큰 작업을 요청** → 컨텍스트가 비대해지고, 하나의 작업에 대한 완성도가 떨어진다.
- **결과물 검수의 가벼움** → 산출물이 한꺼번에 쏟아지면 작업자는 깊이 보지 않고 가볍게 훑고 넘긴다.
- **세션 컨텍스트 오염** → 이전 단계의 잔여 컨텍스트가 다음 단계 판단을 흐린다.
- **범용 프롬프트의 한계** → 모든 단계를 동일한 에이전트가 처리하면 단계별 전문성이 사라진다.

## 제품 컨셉

> **"큰 요구사항을 워크플로우 단위로 잘게 쪼개고, 각 태스크는 새 세션 + 전담 스킬/에이전트로 실행하도록 강제하는 작업 오케스트레이터."**

### 핵심 메커니즘

1. **분해 (Decomposition)**
   사용자가 정의한 Workflow(Step의 순서)에 맞춰 큰 요구사항을 **태스크 단위**로 쪼갠다. 한 태스크 = 한 Step = 한 의도.

2. **세션 격리 강제 (Context Isolation)**
   매 태스크마다 **새로운 세션을 생성**하도록 강제한다. 이전 태스크의 컨텍스트가 다음 태스크로 흘러들지 않게 막아 **컨텍스트 오염을 차단**한다.

3. **인지부하 축소 (Small Flow)**
   작업자(사람)도 한 번에 하나의 좁은 산출물만 보게 되므로, 가볍게 넘기지 않고 **단위별로 깊이 검수**할 수 있다.

4. **전담 스킬/에이전트 매칭 (Quality)**
   각 Step에는 그 단계에 특화된 **스킬 또는 에이전트**를 매칭한다. API 레이어는 API 전문가, 비즈니스 레이어는 비즈니스 전문가 — 단계별 전문성으로 **품질을 챙긴다**.

## 기술 기반

- **Electron + React** (현 프로젝트 구조 그대로) — 로컬-우선 데스크톱 앱.
- **MCP (Model Context Protocol) 기반 실행 계층** — 기존엔 Claude Agent SDK로 태스크를 실행했으나, 구독 요금제로 Agent SDK 사용이 막혔다. 그래서 **MCP 서버 형태로 재구현**하여, 사용자의 Claude Code(또는 호환 클라이언트)가 MCP 도구를 호출하는 방식으로 동일 컨셉을 달성한다.
- **세션 강제 분리**는 MCP 도구 호출 단위로 자연스럽게 구현 — 태스크 실행 = 새 세션 트리거.

## 한 줄 요약

**"개인의 워크플로우대로 요구사항을 잘게 쪼개고, 각 태스크를 새 세션·전담 에이전트로 격리 실행시켜 — 컨텍스트 오염을 막고, 인지부하를 줄이며, 단계별 전문성으로 품질을 끌어올리는 MCP 기반 작업 오케스트레이터."**
