# 프로젝트별 저장 컨셉

## 원칙

> **워크플로우와 태스크는 프로젝트마다 다르다. 그러므로 앱 전역이 아니라 각 프로젝트 디렉토리 내부에 저장하고 관리한다.**

같은 사람이라도 프로젝트가 바뀌면 일하는 방식이 달라진다. 프론트엔드 프로젝트의 워크플로우와 백엔드 데이터 파이프라인 프로젝트의 워크플로우는 같을 수 없다. 따라서 워크OS의 정의 자료(workflow/task/agent 등)는 **그 프로젝트와 같이 살아야** 한다.

## 저장 구조

각 프로젝트의 **루트 디렉토리(`<root>`)** 밑에 표준 위치를 둔다.

```
<프로젝트 루트>/
└── .claude/
    └── workOS/
        ├── workflows/   # 이 프로젝트에서 쓰는 워크플로우 정의
        └── tasks/       # 분해된 태스크 및 실행 산출물
```

- 위치: `<root>/.claude/workOS/`
- 표준 하위 디렉토리: `workflows`, `tasks` (확장 가능)
- 파일은 사람이 읽고 편집 가능한 **텍스트 포맷**(예: `.md`, `.json`)을 우선한다.

## 동작 규약

1. **루트 디렉토리 선택**
   사용자는 워크OS에서 작업할 **프로젝트 루트 디렉토리**(절대 경로)를 선택한다. 빈 경로·상대 경로는 거부한다.

2. **디렉토리 보장(ensure)**
   루트가 정해지면 `.claude/workOS/`와 표준 하위(`workflows`, `tasks`)를 **idempotent하게 보장**한다.
   - 이미 디렉토리로 존재하면 그대로 둔다.
   - 없으면 만든다.
   - 같은 이름의 **파일이 자리를 차지하고 있으면 자동 삭제하지 않고 에러**로 알린다 (사용자 데이터 보호).

3. **프로젝트 전환**
   다른 프로젝트로 루트를 바꾸면, 워크OS가 보는 워크플로우/태스크 컨텍스트도 그 프로젝트의 `.claude/workOS/`로 함께 전환된다. **앱 전역 상태로 끌고 다니지 않는다.**

4. **버전 관리 친화**
   `.claude/workOS/`는 텍스트 기반이므로 프로젝트 저장소에 함께 커밋 가능하다. 팀이 같은 프로젝트를 클론하면, 동일한 워크플로우/태스크 정의를 그대로 공유한다 (1차 버전 기준 옵션, 사용자가 `.gitignore`에 넣을 수도 있음).

## 왜 `.claude/workOS/`인가

- `.claude/` 네임스페이스는 Claude Code 생태계의 관례(스킬, 설정 등)와 동거하기 좋다.
- 향후 위치를 바꾸고 싶으면 (예: `.workos/`) **상수 한 곳**만 수정하면 되도록 경로 세그먼트를 단일 지점에 모아둔다.

## 함의

- **사용자 주권**: 워크플로우/태스크 정의는 사용자 파일시스템 안에 평문 텍스트로 존재 — 언제든 IDE에서 직접 열고 편집·커밋 가능.
- **컨텍스트 격리**(→ [코어 동작](./core-flow.md))와 자연스럽게 맞물린다: 태스크 실행 시 임시 프롬프트 파일도 같은 프로젝트 디렉토리 범위에 둘 수 있어, **그 프로젝트 안에서 모든 일이 일어난다**.
- **로컬-우선** 원칙([PRD N4](./PRD.md))의 구체적 실현 방법이다.

## 한 줄 요약
